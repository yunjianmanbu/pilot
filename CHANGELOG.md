## [0.1.85] - 2026-11-21

0.1.85 rounds out todos and makes the interface quieter. A new 'todos' entry sits at the bottom left of the sidebar and shows how many items are still unsent; opening it lists the todos of every session in one panel instead of hunting session by session. Todos carry a high / medium / low priority: click the tag to cycle it, choose one before typing a new todo, and unsent items are ordered by priority, with the session's scheduled tasks right below the list. A batch of block borders is gone: code blocks, tool output, approval arguments, the trusted-command list and the diff view drop the full outline for a background tint and rounded corners, checked in both light and dark themes. Only the Windows installer ships this round; macOS and Linux stay on 0.1.82, and the CLI and source packages stay on 0.1.76.

## [0.1.84] - 2026-11-21

0.1.84 tidies the session side and makes scrolling back through a long conversation cheap. The four separate buttons for files, knowledge base, links and tools collapse into one "session resources" panel where five kinds of resource — workspace files, related links, available tools, the session knowledge base and files added or changed this session — switch in place and each can be previewed; tools can be enabled, disabled, deleted or promoted to a general tool right there, and files and the knowledge base now use the same monochrome icons as the other entries. The model picker at the top of a session shows only the configured name while collapsed and expands into three lines — name, model id and note — and the connected-model indicator no longer defaults to showing deepseek-chat. When you load earlier messages in a long session, only questions and answers come back: the dozens or hundreds of execution steps from each earlier turn become a single "N steps · not loaded" placeholder, and opening one fetches just that turn and inserts its steps back in place. Only the Windows installer ships this round; macOS and Linux stay on 0.1.82, and the CLI and source packages stay on 0.1.76.

## [0.1.82] - 2026-11-21

This release separates the language the agent thinks in from the language it answers in. There used to be a single rule — follow the user — so a Chinese interface pointed at an English repository reasoned in Chinese, while an English interface with a Chinese message flipped the reasoning back to Chinese; neither matched the UI. Answers still follow the language you write in, but every reasoning block during execution (before, between and after tool calls) is now written in the system language: the language picked in settings, or the OS language when settings are on auto. English tool output, source files and logs no longer drag the reasoning into English, and code, paths, commands, identifiers and quoted text stay exactly as written. The same rule now reaches the review pass, read-only exploration and subagents, so a subtask thinks in the same language as the session that spawned it. Only the Windows installer ships this round; macOS and Linux stay on 0.1.75, and the CLI and source packages stay on 0.1.76.

- Answers still follow the language you write in; reasoning during execution uses the system language
- The system language comes from the app setting, or the OS language when set to auto
- English tool output, source files and logs no longer pull the reasoning into English
- Code, paths, commands, identifiers and quoted text stay exactly as written
- The same rule reaches the review pass, read-only exploration and subagents, so a subtask thinks in the same language as the main session
- Prompt regression tests cover both a Chinese and an English system language
- Desktop 0.1.82 released together with the macOS and Linux 0.1.82 installers; the CLI and source packages stay on 0.1.76

## [0.1.81] - 2026-11-21

This release fixes why a session could grind through hundreds of steps without finishing, and both causes live in the context layer. The previous build let the system-written "continue where you left off" prompt read as a brand new user task: the real request was relabelled closed work, so every resume arrived as a one-line instruction plus a digest and the model re-read the same files from scratch step after step (one file was read 57 times in a single run), until 200 steps ran out and auto-continue stacked another round on top. A persisted continuation prompt now keeps its mark on replay, so a resume belongs to the task it resumes. The second cause is trimming: with only one open task, the cut was pinned to that task itself, so a 614k-token transcript came back untouched under a 20k budget and a longer session only got more expensive per step; the task now survives as the current task and the rest is cut to the shallowest point that fits. Three supporting changes: the compaction summary is persisted and reused, summarizer tokens count against the run usage, and a provider context-overflow error triggers one hard fit at 60% of the budget and a retry instead of failing the run. This round still publishes the Windows installer only; macOS and Linux stay on 0.1.75, and the CLI and source packages stay on 0.1.76.

- A continuation prompt keeps its internal mark, so the "continue" text Pilot writes is never read as a new user task
- In a long session the real request stays labelled the current task instead of being rewritten as closed work to ignore
- A transcript with only one open task is trimmed to the budget instead of being sent in full on every step
- Trimming keeps the current task and as much recent work as fits, so a step no longer drops the whole working set
- The compaction summary is persisted and reused, so the same history is not summarized twice
- Tokens the summarizer spends count against the run usage instead of staying invisible
- A provider context-overflow error triggers one hard fit at 60% of the budget and a retry instead of failing the run
- New regression tests for replay and trimming: resume ownership, single-task trimming, and fitting inside the budget
- Desktop 0.1.81 released; the macOS and Linux installers stay on 0.1.75, and the CLI and source packages stay on 0.1.76

## [0.1.80] - 2026-11-20

Two themes this round: the agent was steering off course, and UI output was hard to get out of the app. Each answer now ends with a change bar listing the files that turn wrote or edited, and a row opens that file in the side panel for preview instead of sending you through the session files list. Selecting text in an answer can add it straight to the todos; with no session open yet one is created first so the selection is never dropped silently. The desktop and mobile clients now pass a self-hosted relay admission code (#k=) end to end, while the dialog and the logs show only the endpoint without the code. Three prompt fixes: a finished task earlier conclusions are no longer carried alongside a new instruction as equal-weight context, a resume after a pause or an automatic plan carry-on counts as the same open task instead of being blocked by the earlier-turns-are-closed rule, and the read-only analysis rules (no edits, about 20 tool calls) are sent only when the turn really is one. Memory entries now carry their age so old ones are re-verified as leads; a checkpoint may only be relabelled from a shell snapshot, so prompt and prerestore boundaries are no longer silently merged away. This round publishes the Windows installer only; macOS and Linux stay on 0.1.75, and the CLI and source packages stay on 0.1.76.

- A change bar under each answer lists the files that turn wrote, and a row opens the file in the side panel
- Selecting text in an answer adds it to the todos; with no session yet one is created first, so the selection is never dropped
- The relay admission code (#k=) is passed through end to end; the dialog and logs show only the endpoint without it
- A finished task earlier conclusions are no longer placed next to a new instruction as the current task
- A resume after a pause or a plan carry-on counts as the same open task, not something the earlier-turns rule closes
- The read-only analysis rules are sent only for a real analysis request, so a change request no longer answers with a report
- Memory entries carry their age, so an old one is re-verified as a lead instead of read as current
- Only a shell snapshot may reuse the previous one, so prompt and prerestore boundaries are no longer merged away
- Reminders Pilot writes itself are labelled INTERNAL by the tool classifier and the reflection transcript, so they are never read as something the user said
- Desktop 0.1.80 released; the macOS and Linux installers stay on 0.1.75, and the CLI and source packages stay on 0.1.76

## [0.1.78] - 2026-11-20

This release fixes an old Windows annoyance: clicking the tray icon made the taskbar button disappear and a new one appear, as if the app had closed and restarted. The tray click used to toggle — clicking it while the window was open hid it to the tray, Windows immediately dropped the matching taskbar button, and the next click created a fresh one. The tray click now only ever brings the window up: show it when hidden, restore it when minimised, focus it when it is already in front, and never hide it. Hiding stays on the tray menu Hide Pilot item and on the window close button, where the user asked for it by name. Double-click no longer flashes either: Windows sends a single click before the double-click, so the old click-hides / double-click-shows pair always hid and re-showed, and both callbacks now take the same idempotent path. Launching again from the Start menu or a shortcut also brings a hidden window back to the front. Only the Windows installer ships this round; macOS and Linux stay on 0.1.75, and the CLI and source packages stay on 0.1.76.

- A tray click only brings the window back (show / restore / focus) instead of hiding it
- Windows no longer removes and recreates the taskbar button; it is the same button before and after the click
- Hiding stays on the tray menu Hide Pilot item and the window close button
- A double-click no longer hides first; single and double clicks take the same idempotent path
- Relaunching from the Start menu or a shortcut brings a hidden window back to the front
- New window-action unit tests: no window state maps a tray click to hiding

## [0.1.77] - 2026-11-20

This release adds a gate in front of the self-hosted relay. The installer now generates a random WebSocket path and an admission code, and prints one connection string shaped like wss://relay.example.com/c/<random>#k=home:<random>; the desktop and phone apps pass everything after #k= through to the relay, while the UI only ever shows the address without the code, so a screenshot or a log line cannot leak it. A relay without keys behaves exactly like 0.2.2; once keys are configured the default is to record rejections without enforcing (RELAY_ACCESS_STRICT=0), so you can switch it to 1 after every client has updated instead of locking yourself out mid-upgrade. What it stops is a leaked address being used as free relay bandwidth; message contents stay the job of end-to-end encryption. The site also ships a long read, Why the relay wants a ticket, covering the trade-off and the trap we hit. This round still publishes the Windows installer only; macOS and Linux stay on 0.1.75, while the CLI and source packages stay on 0.1.76.

- Relay 0.2.3: the installer generates a random /c/<random> path and a home:<random> admission code, and prints the whole connection string
- Desktop and phone pass everything after #k= through, and the UI shows only the address without the code
- The relay checks the code before creating a room and rejects a bad one with 4009; /healthz exposes anonymous and rejected counters
- RELAY_ACCESS_STRICT=0 records without enforcing by default; switch it to 1 once every client is updated
- Desktop 0.1.77 released; the macOS and Linux installers stay on 0.1.75, and the CLI and source packages stay on 0.1.76
- New article: Why the relay wants a ticket — what an admission code protects and what it does not

## [0.1.75] - 2026-11-20

This release fixes evolution profiles being evicted by drafts. The archive holds forty records and used to trim by position, so a shelf full of drafts could cut the oldest active version, leaving the current version empty in the UI and dropping its rules from the prompt. Records are now kept in the order active > measured winner > draft, and loading and saving share one rule set, with the UI stating built-in default when nothing is active. Three other changes: each turn treats only the newest user message as the task instead of resuming an unfinished plan from the previous turn, asking first when continuation is genuinely needed; tool definitions are compared by name set, so pure additions keep the definitions already sent intact instead of refreshing the whole block when MCP tools change; and when a command is missing (exit code 127 / 9009 or ENOENT) the result now lists the project's own test and build entry points.

- Evolution profiles are kept in active > measured winner > draft order, so no amount of drafts evicts an active version
- Loading and saving share one pruning rule; with nothing active the UI says built-in default
- Each turn treats only the newest user message as the task and no longer auto-resumes an unfinished plan from the previous turn
- Tool definitions are compared by name set, so a pure addition leaves already-sent definitions untouched
- When a command is missing (127 / 9009 / ENOENT) the result lists the project's own test and build entry points
- Desktop 0.1.75 released; CLI and source packages synced to 0.1.75

## [0.1.74] - 2026-11-20

This release takes the cost out of checkpoints. Scratch, build-output and log directories are excluded by default, which on this repository cut the snapshot set from 74,791 files to about 1,200 and a scan from 24 seconds to 0.36 s. When nothing changed between two commands the previous snapshot is reused, measured at 3 ms, so long tasks no longer re-walk the tree on every step. Sessions on different workspaces stop queueing behind one another. A newly created directory is judged at the moment its first file is written, excluded immediately with a note in the session instead of waiting for the next full scan. Reverting a checkpoint keeps those generated directories instead of deleting them and forcing a rebuild.

- Generated directories (tmp, build output, logs) stay out of snapshots by default; this repository went from 74,791 files to about 1,200
- Scan time dropped from 24 s to 0.36 s, and an unchanged tree reuses the previous snapshot in a measured 3 ms
- Checkpoints on different workspaces run in parallel instead of queueing
- A new directory is judged and excluded as soon as its first file is written, no full rescan needed
- Reverting keeps generated directories instead of deleting them and forcing a rebuild
- Desktop 0.1.74 released; CLI and source packages synced to 0.1.74
